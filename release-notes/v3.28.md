# v3.28

Download More addons now install no matter how their creator packs or names a release. The launcher checks what is inside each download and takes the addon's folder from it, falling back to the release's source code when no ZIP holds it. GitHub's hourly request limit no longer stops an install, and addons that went into AddOns\AddOns are moved to the AddOns folder the game reads.

- Every file of an addon's latest release is tried in turn, most likely first; the first one holding the addon's folder (its .toc file) is installed. When none does, the release's source code is used. This is why CreedUI 1.14.3, whose release has no ZIP attached, now installs.
- An addon inside an extra folder, or with its files loose at the top of the ZIP, installs into the folder the game needs. When a download holds two copies of an addon, the newer version is kept.
- Loose files beside an addon, such as readmes, are no longer copied into the AddOns folder, which ends the "Cannot create a file when that file already exists" error.
- When GitHub's hourly request limit is reached, the launcher uses its last saved copy of the release, or the release's own web page, instead of stopping.
- Release files without a published SHA-256 digest (older uploads and source code) install over https. A file whose published digest does not match is still never installed.
- If the AddOns folder was picked where the benilla-config folder belongs, addons go to that AddOns folder. Addons that earlier landed in AddOns\AddOns are moved up when the launcher starts.
